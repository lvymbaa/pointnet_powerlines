## Описание проекта

Система предназначена для автоматизации мониторинга технического состояния воздушных линий электропередачи класса напряжения 6–35 кВ на основе данных лазерного сканирования местности (LiDAR). Входными данными служат облака точек в формате **LAS**, полученные при аэросъёмке трассы ЛЭП. Система выполняет:

1. **Семантическую сегментацию** облака точек с выделением классов «земля», «растительность» и «провода ЛЭП» с помощью нейронной сети **PointNet**;
2. **Геометрическую постобработку** результатов классификации для подавления ложных срабатываний класса «провода» (кластеризация DBSCAN + анализ линейности методом PCA);
3. **Автоматическое построение охранных зон** вдоль трассы ЛЭП в соответствии с нормативными требованиями (ПУЭ, ±10 м для ВЛ 6–35 кВ);
4. **Анализ зарастания охранной зоны** древесно-кустарниковой растительностью с расчётом доли точек кроны, пересекающих плоскость провиса провода.

Проект реализован в виде клиент-серверного веб-приложения: серверная часть на **Python/FastAPI** выполняет вычислительно тяжёлые операции (инференс нейросети, кластеризация, геометрические расчёты), клиентская часть — интерактивная 3D-визуализация на **Three.js**, исполняемая непосредственно в браузере.

## Ключевые возможности

| Функция | Описание |
|---|---|
| Классификация облака точек | Посегментная (patch-based) сегментация нейросетью PointNet с голосованием по нескольким проходам (multi-pass voting) |
| Геометрическая фильтрация | Устранение ложных срабатываний класса «провода» через DBSCAN-кластеризацию и PCA-анализ линейности/вытянутости кластера |
| Просмотр готовой классификации | Визуализация LAS-файлов, уже содержащих атрибут `classification`, без повторного запуска нейросети |
| Расчёт охранных зон | Автоматическое построение ограничительных плоскостей вдоль каждого пролёта ЛЭП на заданном нормативном расстоянии |
| Анализ зарастания | Проекция точек растительности в коридор охранной зоны, расчёт процента точек, превышающих уровень провиса провода |
| Интерактивная 3D-визуализация | Progressive LOD-рендеринг облаков точек объёмом до нескольких миллионов точек в браузере (Three.js / WebGL) |
| Обучение модели | Готовый ноутбук для дообучения PointNet на собственных размеченных данных в Google Colab |

## Описание модулей

### `api.py` — серверная часть (FastAPI)

Центральный модуль системы (≈1190 строк), реализующий всю вычислительную логику. Работает как автономный ASGI-процесс, слушающий порт **8000**.

**Зависимости модуля:** `fastapi`, `uvicorn`, `torch`, `torch.nn`, `torch.nn.functional`, `numpy`, `laspy`, `sklearn.cluster.DBSCAN` (импортируется лениво, внутри обработчиков), `pydantic`.

Ключевые компоненты:

- **Архитектура нейронной сети `PointNetSeg` + `TNet`.** Реализация PointNet для семантической сегментации облаков точек с T-Net-модулем выравнивания признакового пространства (feature alignment, k=64). Сеть принимает точки с 6 признаками на вход `(B, N, 6)` — нормализованные `X, Y, Z`, высота, интенсивность отражённого импульса и отношение номера возврата к общему числу возвратов (`return_number / number_of_returns`), и возвращает поточечные логиты для 3 классов: земля, растительность, провода.
- **Загрузка модели (`try_load_model`).** При старте приложения (`@app.on_event("startup")`) загружается чекпоинт по пути, заданному константой `CHECKPOINT`; конфигурация архитектуры (`num_classes`, `in_features`) восстанавливается из самого чекпоинта. Автоматически определяется доступность CUDA.
- **Патч-инференс с голосованием (`run_classification`).** Поскольку PointNet принимает облака точек фиксированного размера (`PATCH_SIZE = 2048`), исходное облако произвольного размера нарезается на пересекающиеся локальные патчи (k ближайших соседей по XY-плоскости), классифицируется батчами (`BATCH_SIZE = 16`), а итоговая метка точки определяется голосованием (суммированием логитов) по `NUM_PASSES = 3` независимым проходам. Точки, не получившие ни одного голоса (типично для разреженных проводов), дополнительно обрабатываются целевым проходом, где они принудительно назначаются центрами патчей.
- **Геометрическая фильтрация ложных срабатываний (`filter_powerlines`, функция `pca_linearity`).** Точки, классифицированные как «провода» (LAS-класс 14), кластеризуются алгоритмом **DBSCAN**; для каждого кластера методом главных компонент (**PCA**) вычисляются метрики линейности `(λ₁-λ₂)/Σλ` и вытянутости (отношение размахов проекций на первую и вторую главные оси). Кластеры, не удовлетворяющие пороговым значениям линейности, вытянутости или минимального числа точек, переклассифицируются в резервный класс (`fallback_cls`, по умолчанию — неклассифицировано).
- **Расчёт охранных зон (`safety_zones`, `safety_zones_from_labels`).** Провода разбиваются DBSCAN на отдельные пролёты; для каждого пролёта методом PCA определяется главная ось (направление провода), после чего строятся две вертикальные ограничительные плоскости, смещённые на заданное расстояние `distance` по горизонтальной нормали к оси провода. Высота плоскости — от уровня земли (медиана Z точек класса «земля») до верхней точки провода с запасом.
- **Анализ зарастания растительностью (`vegetation_projection`).** Провода разбиваются на пролёты; для каждого пролёта определяется высота точки максимального провиса (5-й перцентиль Z); точки класса «растительность», попадающие в горизонтальный коридор охранной зоны, проецируются на плоскость сечения, после чего рассчитывается процент точек кроны, превышающих критическую высоту.
- **REST-эндпоинты** (подробное описание — см. раздел «Описание REST API»): `GET /health`, `POST /classify`, `POST /classify_filtered`, `POST /view`, `POST /filter`, `POST /safety_zones`, `POST /safety_zones_from_labels`, `POST /vegetation_projection`.
- **CORS** настроен максимально широко (`allow_origins=["*"]`) для упрощения локальной разработки и взаимодействия со статическим фронтендом на другом порту.

### `index.html` — веб-интерфейс (Three.js)

Однофайловое SPA-приложение (≈1840 строк: CSS + HTML + JavaScript без сборочных инструментов и внешних фреймворков), реализующее весь пользовательский интерфейс и 3D-визуализацию.

**Внешние зависимости (подключаются через CDN):**
- `three.js` r128 (`cdnjs.cloudflare.com`);
- `THREE.OrbitControls` (`cdn.jsdelivr.net`).

Ключевые компоненты:

- **Панель управления (sidebar)** — загрузка LAS-файла (drag-and-drop либо диалог выбора), переключение из четырёх режимов обработки («Классификация», «Классификация + фильтрация», «Просмотр», «Геофильтрация»), настройка параметров геометрической фильтрации и охранных зон, легенда классов LAS, статистика обработки.
- **3D-сцена на Three.js** — облако точек рендерится как `THREE.Points`; реализована система **прогрессивного LOD (Level of Detail)**: все точки облака хранятся в едином `Float32Array`, но отображается лишь часть точек (`DrawRange`), объём которой динамически регулируется в зависимости от расстояния камеры до сцены (`LOD_LEVELS` — от 5% точек при удалённом виде до 100% при приближении), что обеспечивает плавный рендеринг облаков объёмом в сотни тысяч – единицы миллионов точек.
- **Управление камерой** через `OrbitControls`: вращение (ЛКМ), панорамирование (ПКМ), масштабирование (колесо), сброс вида (двойной клик).
- **Взаимодействие с бэкендом** — все операции обработки выполняются через `fetch()`-запросы к REST API (`API_URL = 'http://localhost:8000'`) с передачей файла как `multipart/form-data` либо (для повторных расчётов на уже классифицированном облаке) JSON-объекта координат и меток.
- **Визуализация охранных зон и зарастания** — полупрозрачные плоскости и точки проекции растительности отрисовываются как дополнительные объекты сцены поверх основного облака точек.

### `server.js` — HTTP-сервер статики (Node.js)

Минималистичный HTTP-сервер (38 строк) на базе встроенных модулей Node.js (`http`, `fs`, `path`) без внешних npm-зависимостей. Раздаёт `index.html` и сопутствующие статические файлы на порту **3000**; для всех несуществующих путей выполняется fallback на `index.html` (паттерн single-page приложения).

### `pointnet_colab.py` / `pointnet_colab.ipynb` — обучение нейросети

Автономный скрипт/ноутбук (467 строк), предназначенный для запуска в среде **Google Colab** с GPU-акселератором (рекомендуется T4). `pointnet_colab.py` — экспортированная в `.py` версия ноутбука `pointnet_colab.ipynb` (идентичен по содержанию, отличается только форматом).

**Зависимости:** `torch`, `torch.nn`, `torch.optim`, `torch.amp` (автоматическое смешанное вычисление точности), `torch.utils.data` (`Dataset`, `DataLoader`), `laspy`, `numpy`, `tqdm`, `matplotlib`, `google.colab` (специфично для среды Colab).

Ключевые компоненты:

- **`FastLASDataset`** — датасет с предварительной нарезкой (pre-cutting) патчей фиксированного размера (`patch_size = 2048`) один раз при инициализации, что ускоряет последующие эпохи обучения. Реализована **гиперсэмплировка (oversampling)** редкого класса «провода» с коэффициентом `powerline_oversample = 10` для борьбы с дисбалансом классов. Для обучающей выборки применяется аугментация данных: случайный поворот вокруг вертикальной оси, случайное масштабирование (0.9–1.1), гауссов джиттер координат, случайное отражение по оси X.
- **Архитектура модели** — идентична используемой в `api.py` (`PointNetSeg` + `TNet`), с той разницей, что при обучении включён `Dropout` (`p = 0.3`).
- **`FocalLoss`** — функция потерь Focal Loss с настраиваемыми весами классов (`class_weights = [1.0, 1.5, 25.0]` — усиленный вес класса «провода») и параметром фокусировки `gamma = 2.0`, применяется для борьбы с сильным дисбалансом классов (провода составляют малую долю точек облака).
- **Цикл обучения** — с накоплением confusion-матрицы, расчётом mIoU и overall accuracy (OA) по эпохам; отдельно сохраняются лучший чекпоинт по общему mIoU (`best_model.pt`) и лучший чекпоинт по IoU именно класса «провода» (`best_powerlines.pt` — используется продуктивной системой), а также периодические снимки (`ckpt_epoch{N}.pt`) и журнал обучения `train_log.json`.
- **Оптимизация** — Adam с `StepLR`-планировщиком, обучение со смешанной точностью через `GradScaler`/`autocast` для ускорения на GPU с ограниченным объёмом видеопамяти (совместимо с бесплатным тарифом Google Colab).
- **Экспорт результатов** — по завершении обучения формируется архив с чекпоинтами, файлом параметров нормализации (`norm_params.pkl`), логом обучения и графиками (`curves.png`), который скачивается через `google.colab.files.download`.

### `checkpoints/best_powerlines.pt`

Файл весов обученной модели PointNet (~31 МБ), содержащий словарь состояния модели (`model_state`), состояние оптимизатора (`opt_state`), номер эпохи, конфигурацию архитектуры (`config`) и валидационные метрики (`val_miou`, `pw_iou`), достигнутые на момент сохранения. Загружается сервером `api.py` при старте; согласно руководству пользователя, для эталонного набора данных модель достигает **mIoU ≈ 87 %** и **IoU класса «провода» ≈ 91 %** (значения зависят от обучающей выборки и не гарантируются для произвольных данных).

## Формат входных данных

Система работает с файлами формата **LAS** (LiDAR Aerial Survey — стандартный бинарный формат хранения данных лазерного сканирования). Используются следующие атрибуты точек:

| Атрибут LAS | Использование |
|---|---|
| `X, Y, Z` | Пространственные координаты точки |
| `intensity` | Интенсивность отражённого импульса (признак модели) |
| `return_number`, `number_of_returns` | Номер и общее число возвратов импульса (признак модели) |
| `classification` | Метка класса точки (используется в режимах «Просмотр» и «Геофильтрация», а также как целевая переменная при обучении) |

Классы LAS, задействованные в системе:

| Код класса | Название | Цвет в визуализации |
|---|---|---|
| 2 | Земля (ground) | коричневый |
| 4 | Растительность (medium vegetation) | зелёный |
| 14 | Провода ЛЭП (powerlines) | красный |
| 1 | Неклассифицировано (unclassified) | серый |

Модуль `/view` дополнительно поддерживает расширенный набор стандартных LAS-классов (здания, вода, дорожное покрытие, опоры и др.) для целей визуализации, не требующей повторного инференса.

## Описание REST API

Все эндпоинты принимают данные в формате `multipart/form-data` (загрузка LAS-файла) либо JSON (для операций над уже переданным облаком точек) и возвращают JSON-ответ с координатами точек, цветами, метками классов и статистикой обработки. Интерактивная документация — `http://localhost:8000/docs`.

| Метод | URL | Описание |
|---|---|---|
| `GET` | `/health` | Статус сервера и факт загрузки модели |
| `POST` | `/classify` | Классификация LAS-файла нейросетью PointNet |
| `POST` | `/classify_filtered` | Классификация + геометрическая фильтрация проводов за один запрос |
| `POST` | `/view` | Визуализация уже классифицированного LAS-файла (без запуска нейросети) |
| `POST` | `/filter` | Геометрическая фильтрация существующей классификации без повторного инференса |
| `POST` | `/safety_zones` | Расчёт охранных зон непосредственно из LAS-файла |
| `POST` | `/safety_zones_from_labels` | Расчёт охранных зон по ранее переданному (отфильтрованному) облаку точек |
| `POST` | `/vegetation_projection` | Анализ зарастания охранной зоны растительностью |

### Параметры геометрической фильтрации (`/filter`, `/classify_filtered`)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `linearity` | 0.80 | Минимальная линейность кластера (PCA, 0–1) |
| `elongation` | 3.0 | Минимальное отношение длины кластера к ширине |
| `min_points` | 10 | Минимальный размер кластера, ниже которого он считается шумом |
| `eps` | 0.8 м | Радиус соседства DBSCAN |
| `min_samples` | 3 | Минимальное число точек для формирования ядра кластера DBSCAN |
| `fallback_cls` | 1 | Класс, присваиваемый точкам, отфильтрованным как ложные |

## Обучение модели на собственных данных

1. Подготовьте размеченный LAS-файл, где атрибут `classification` содержит значения: `2` (земля), `4` (средняя растительность), `14` (провода ЛЭП).
2. Загрузите файл на Google Drive, например в `MyDrive/les_data/cloud_train.las`.
3. Откройте `pointnet_colab.ipynb` в Google Colab (загрузка ноутбука напрямую либо через Google Drive).
4. Смените среду выполнения: **Runtime → Change runtime type → T4 GPU**.
5. В ячейке настройки путей укажите свои значения:
   ```python
   LAS_FILES = ["/content/drive/MyDrive/les_data/cloud_train.las"]
   CHECKPOINT_DIR = "/content/drive/MyDrive/les_data/checkpoints"
   ```
6. Выполните оставшиеся ячейки по порядку.

### Основные гиперпараметры обучения

| Параметр | Значение | Описание |
|---|---|---|
| `patch_size` | 2048 | Число точек в одном патче |
| `num_patches` | 800 | Число патчей на файл |
| `powerline_oversample` | 10 | Коэффициент гиперсэмплировки класса «провода» |
| `val_split` | 0.15 | Доля данных для валидации |
| `in_features` | 6 | XYZ + высота + интенсивность + возврат |
| `num_classes` | 3 | Земля, растительность, провода |
| `dropout` | 0.3 | Вероятность отсева |
| `class_weights` | [1.0, 1.5, 25.0] | Веса классов в Focal Loss |
| `epochs` | 60 | Число эпох |
| `batch_size` | 32 | Размер батча |
| `lr` | 0.001 | Начальная скорость обучения (Adam) |

По завершении обучения файл `best_powerlines.pt` необходимо скачать из Google Drive, поместить в директорию `les_monitor/checkpoints_fast/` и перезапустить `api.py`.

## Устранение неисправностей

| Проблема | Возможная причина | Решение |
|---|---|---|
| Страница не загружается | Node.js-сервер не запущен | Выполните `node server.js` |
| API не отвечает | Python-сервер не запущен | Выполните `python api.py` |
| «Модель не загружена» | Неверный путь к `.pt`-файлу | Проверьте константу `CHECKPOINT` в `api.py` |
| Ошибка 400 «Нужен .las файл» | Загружен файл другого формата | Используйте только файлы `.las` |
| Классификация выполняется очень медленно | GPU недоступен | Установите сборку PyTorch с поддержкой CUDA |
| Провода не обнаружены | Провода не попали в патчи | Увеличьте `NUM_PASSES` в `api.py` |
| Много ложных проводов | Низкие пороги фильтрации | Увеличьте параметры «Линейность» и «Вытянутость» в интерфейсе |
| Ошибка `scikit-learn` | Библиотека не установлена | Выполните `pip install scikit-learn` |

## Ограничения текущей версии

- Модель обучена и валидирована на ограниченном наборе данных; для обеспечения устойчивого качества сегментации на новых площадках рекомендуется дообучение (fine-tuning) на репрезентативных данных конкретного региона/трассы.
- Сервер сконфигурирован для локального развёртывания (CORS `allow_origins=["*"]`, отсутствие аутентификации); для промышленной эксплуатации требуется дополнительная защита API.
- В браузер передаётся не более 250 000 точек на облако (провода — полностью, остальные классы прореживаются случайной выборкой); рекомендуемый верхний предел исходного файла — 5 000 000 точек.
- Обучение вынесено во внешнюю среду Google Colab и не автоматизировано как часть продуктивного контура.

## Глоссарий

| Термин | Определение |
|---|---|
| **LAS** | Стандартный бинарный формат хранения данных лазерного сканирования (LiDAR Aerial Survey) |
| **LiDAR** | Метод дистанционного зондирования на основе лазерного излучения для получения 3D-облаков точек |
| **PointNet** | Нейросетевая архитектура для обработки неупорядоченных облаков точек (Qi et al., 2017), с T-Net-модулем в данной реализации |
| **DBSCAN** | Density-Based Spatial Clustering of Applications with Noise — алгоритм кластеризации на основе плотности точек |
| **PCA** | Метод главных компонент, используется для оценки линейности и вытянутости кластеров |
| **Охранная зона ЛЭП** | Зона вдоль трассы ВЛ с ограничением хозяйственной деятельности; для ВЛ 6–35 кВ составляет ±10 м от крайних проводов согласно ПУЭ |
| **mIoU** | Mean Intersection over Union — усреднённая по классам метрика качества сегментации |
| **FastAPI** | Высокопроизводительный Python-фреймворк для построения веб-API на базе ASGI и Pydantic |
